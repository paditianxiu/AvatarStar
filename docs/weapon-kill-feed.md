# 武器击杀来源

当前客户端 `C:\Game\AvatarStar\client.exe` 的 packet184 处理函数为冲撞技能（Spurt）命中。此前服务端将普通武器伤害也发成 packet184，导致击杀栏固定显示技能图标。

普通武器命中使用 packet113，将该次开火、武器槽位和目标剩余血量放入同一条消息。AI 命中时不再额外发送一条无伤害的开火消息；同帧切枪先通过 packet128 同步。未命中沿用原 packet113。投射物命中确认使用 packet121，并保存发射时的开火记录，避免发射者切枪后使用另一把武器作为击杀来源或重复生成投射物。

## 原生客户端证据

地址来自当前客户端解包后的 x86 映像，基址为 `0x400000`。网络分派函数为 `0x5D6570`。

| 消息 | 处理函数 | 行为 |
| --- | --- | --- |
| 113 | `0x5D43E0` | 武器开火和命中，击杀来源使用当前武器 |
| 121 | `0x5C4300` | 投射物命中，按消息中的原槽位取武器，不重复发射 |
| 184 | `0x5C7E00` | Spurt 技能命中，固定技能来源并使用 `go/impact_3d/impact_spurt` |

113 和 121 的目标血量标志为 `0x00100000`（bit20）。不要照搬 packet184 的 `0x00004000`：在武器消息中该位属于攻击者计分。对象 delta 解析函数为 `0xBCF110`，共同受击／死亡函数为 `0x5C36A0`。

## 发出的帧

偏移包含消息号。消息号、普通整数及压缩坐标沿用 PacketWriter 的字节序；flags 为大端。

| 字段 | 普通命中 113 | 投射物命中 121 |
| --- | --- | --- |
| 消息号 | offset 0，2 字节 | offset 0，2 字节 |
| flags | offset 2，`0x00F0000F` | offset 2，`0x00700007` |
| 攻击者 UID | offset 6 | offset 6 |
| 目标 UID | offset 7 | offset 7 |
| 武器槽位（1 起始） | offset 8 | offset 8 |
| 播放开火动作 | offset 9，值 1 | 无 |
| 目标剩余血量 int32 | offset 10 | offset 9 |
| origin，6 字节 | offset 14 | offset 13 |
| vector，6 字节 | offset 20 | offset 19 |
| facing，4 字节 | offset 26 | 无 |
| 总长 | 30 字节 | 25 字节 |

未命中 113 保留 flags `0x00E0002D`，offset 9 为跳过目标标记 `0xFE`，总长 26 字节。无武器来源的旧技能伤害及血量同步仍走已有路径；武士技能伤害不会继承触发反击的敌方武器。

## 验证

`tests/AvatarStar.Game.Tests/KillFeedTests.cs` 新增 28 项检查；全套 539 项通过。检查三个槽位的普通／致死命中、攻击者／目标／旁观者收到单条合并消息、未命中、投射物错误槽位拒绝及切枪后的原槽位保留，并驱动真实 AI 决策步生成击杀。测试按 AI 的反应时间推进多个决策步。

这是服务端修复，无需修改 Lua 或 PDE。封包检查不能代替客户端击杀栏的实际画面验收。
