# 房间 AI 玩家

房间底部“返回”和“邀请”之间增加“添加 AI”。房主在准备阶段可选择红队或蓝队、护卫／重装／突击／生化专家／武士，以及 1–8 名 AI。每队最多 8 人，仍受房间总人数限制；批量添加失败时不会只添加一部分。面板可移除所选队伍的全部 AI。

面板新增“一键随机填满”：忽略单独添加所选的队伍、职业和数量，按房间人数上限一次补齐空余战斗位置。优先补人数较少的队伍，人数相同时随机选队；每名新增 AI 的职业从五种职业中独立随机选择，武器和商店造型也随机。16 人房间只有房主时添加 15 名 AI，最终红蓝各 8 人。已有真人和 AI 的槽位、职业、装备及外观均保留；不向旁观槽添加 AI，已有旁观成员仍计入房间人数。满房重复点击不会新增或重新随机现有玩家。

AI 从商店当前可用的 27 张造型卡中随机选择完整外观，保留所选职业及其三类随机武器。空白部件会清除原职业服装，避免混搭残留；商城卡片本身不会被修改。角色仅在房间内存中存在，不加入账号角色列表。比赛开始后采用独立 UID，并使用正常角色创建、移动、切枪、射击、伤害、死亡及重生协议。

目前提供地图 **50、51、52、53** 的导航数据。导航从解包目录的 PhysX 三角网格生成，包含站立空间、台阶、身体宽度和碰撞检查。AI 沿可行走边进行 A* 寻路；每次规划使用稳定的随机区域代价，并对拥挤位置和其他 AI 的站位目标加价。分散出生点、独立包抄方向、不同速度／攻击距离、目标分配及错开的重新规划时间，减少相同路线和落点。

移动时扫掠整个步长，角色间保留 1.05 米间隔；堵塞后沿可行走边侧让或后退，轮换通行优先级，避免同一角色一直抢占通道。不同楼层分别判断。攻击前检测视线，按距离选择武器，具备反应延迟、瞄准偏差、弹匣／换弹时间和低血量拉开距离。没有敌人时巡逻，死亡后停止行动，三秒后选择空闲出生位置重生。最后一位真人离开时停止循环，房主关房后清理 AI。

不支持导航的地图和远征模式会在添加时提示。当前默认地图 6（LEVEL11）在指定资源目录中只有旗帜碰撞缓存，不能据此生成可靠的场景导航。AI 目前使用普通武器攻击，尚未加入主动职业技能决策。地图机关、夺旗和占点的专门策略不在本次实现中。

## 客户端打包

实际修改文件：`C:\Game\AvatarStar\AvatarStar.pde`，资源路径 `scripts/lobby/playgame.lua`。

`client-patches/room-ai.lua` 使用游戏自带 `tools/Lua/luac.exe` 编译。安装器将原房间脚本的整个函数原型逐字节嵌入包装脚本，再调用新增 UI 函数；不反编译重建原脚本，也不依赖运行时 loadstring。新增控件初始化有错误隔离，避免影响进入大厅。

安装时先复制 PDE 验证，再追加独立 FAT／数据块，最后更新目标目录项。原数据链和其他资源均保留，原有汉化和地图补丁不变。当前“一键随机填满”版本的编译字节码、原文件备份及安装清单位于 `.tmpbuild/room-ai/client-patch-fill`。

```powershell
node client-patches/install-room-ai.mjs prepare C:/Game/AvatarStar/AvatarStar.pde .tmpbuild/room-ai/client-patch-fill
node client-patches/install-room-ai.mjs apply C:/Game/AvatarStar/AvatarStar.pde .tmpbuild/room-ai/client-patch-fill
# 还原最近一次安装的目录指针
node client-patches/install-room-ai.mjs rollback C:/Game/AvatarStar/AvatarStar.pde .tmpbuild/room-ai/client-patch-fill
```

修改 PDE 后必须完全退出并重新启动客户端。

## 服务端与验证

RPC 为 `room_ai_add`、`room_ai_remove` 和 `room_ai_fill`。填满 RPC 仅使用 `roomUid`，服务端自行计算空位并随机职业。原生房间界面的 `RoomUid` 实际为频道 RoomId（如 1），大厅房间列表使用打包后的 RoomUid（如 65537）；服务端兼容两者并检查房主身份。

```powershell
node client-patches/build-ai-navigation.mjs
dotnet build tests/AvatarStar.Game.Tests/AvatarStar.Game.Tests.csproj --artifacts-path .tmpbuild/room-ai/artifacts
dotnet .tmpbuild/room-ai/artifacts/bin/AvatarStar.Game.Tests/debug/AvatarStar.Game.Tests.dll 'C:\Code\c#\AvatarStar'
```

测试覆盖原武士功能、导航绕墙与视线、四张地图出生点连通性、五职业造型和随机武器、房间编号兼容、权限／容量、UID 隔离、协议广播、真人和 AI 互伤、死亡重生及离房清理。

验证结果：539 项检查通过，覆盖双客户端隐身／冲刺技能归属、商城造型完整性、随机分路、拥挤路线选择和 15 名 AI 持续移动的间距／速度／碰撞测试。一键填满新增 47 项检查，包含 16 人／小人数／奇数上限、单队已满、旁观成员、职业和装备有效性、权限、无效配置、保留原成员以及并发重复请求不超员。武器击杀图标修复新增 28 项检查，覆盖三个武器槽位的普通／致死命中、未命中、投射物切枪后的原武器来源、AI 实际攻击来源，以及攻击者／目标／旁观者的广播帧。

用户已确认前一版 PDE 可以进入大厅；服务器已收到原生面板的添加／移除 AI RPC。2026-11-06 22:13 的实际地图 53 对局中，已记录 AI 出生／入场、战斗和自动重生广播。角色选择卡住问题通过移除运行时二次加载字节码解决。本次新增按钮已通过 Lua 编译与 PDE 回读校验，仍需在客户端中确认实际显示和点击效果；完整局内画面与动画不能以服务端日志代替。

队友隐身／冲刺触发本地技能的修复：packet160 槽位激活回执只发给施法者，发送函数也拒绝非本地 UID。其他客户端仅接收以施法者为 actor／target 的 packet162 效果及 packet155 关闭同步，落点技能继续使用 packet185。武士反击的槽位激活同样仅发给反击者本人。

武器击杀固定显示紫色技能图标的修复：当前客户端将 packet184 解释为冲撞技能命中，因此不能用它广播普通武器伤害。普通武器命中改为携带实际开火槽位和目标血量的 packet113，命中时不再另发重复开火帧；延迟投射物命中使用 packet121，保留发射时的槽位。AI 在攻击前同步切枪，击杀来源来自该次实际使用的武器。协议证据与帧布局见 [武器击杀来源](weapon-kill-feed.md)。本次仅更新服务端，不修改 PDE；自动检查验证封包内容，实际击杀栏画面仍需客户端确认。
