# 武士模型、技能与效果

实现入口：`Models/SamuraiAppearance.cs`、`Models/SamuraiSkills.cs`、`PracticeRooms/PracticeRoomManager.Samurai.cs`。职业编号仍为 `occupation=4`、创建编号为 `jobId=5`。

## 资源与数值来源

参考目录为 `tools/Unpack/AvatarStar`。`skill/samurai_*.lua.cache` 解压后定义技能图标、音效、`AddCastEffect` 和 `CastAnimation`；`buff/69.lua.cache` 绑定 `samurai_guard` 到 `back_b`，`buff/89.lua.cache` 绑定 `samurai_bushido` 到 `root`。

解包目录的 `scripts/newsys/class/samurai.lua` 是不完整的反编译文本，`SKILLS` 等初始化表达式丢失。因此只读取它的数值，并与已汉化实际资源包中的完整字节码交叉核对，没有用反编译文本覆盖客户端。原数组有六个元素，最后两个相同；服务端沿用原有五级上限，取前五项。

Lua 没有定义服务端技能编号。本实现分配空闲编号 80～84，85 为不可手动释放的反击辅助技能。它们不是从原服抓包恢复的编号，不能与 buff 编号混用。

| 技能编号 | 技能 / resource | 1～5 级数值 | 冷却（秒） |
| --- | --- | --- | --- |
| 80 | 居合斩 / samurai_iaislash | 伤害 300/350/400/450/500；4.5 米、120° 扇形 | 14/13/12/11/10 |
| 81 | 风步 / samurai_windstep | 伤害 250/300/350/400/450；前进 7 米，路径敌人每次只命中一次 | 16/15/14/13/12 |
| 82 | 风切 / samurai_windcut | 伤害 280/330/380/430/480；长 12 米、宽 2 米 | 15/14/13/12/11 |

格挡只对 8 米内的攻击者触发：减少本次伤害、消耗格挡、接近攻击者并反击。远程攻击不消耗格挡。反击使用辅助槽位 16 的 `samurai_counter`；客户端无法通过 136 手动使用它。

## 服务端行为

- 136 请求在房间锁内检查玩家与连接身份、职业、实际技能等级、存活、阵营、位置及冷却，再结算一次伤害。未加点技能不可释放。
- 160 驱动施法动画；162 打开格挡或武士道特效；155 在消耗、死亡或到期时关闭。伤害和击退发给整个房间，包含施法者。
- 武士的 152 请求不会重复结算或套用其他职业的放置物协议。
- 风步与反击更新服务端位置，通过现有 111/110 路径同步本人与其他玩家。
- 武器伤害路径也经过格挡和武士道计算；技能伤害不额外享受武士道的武器增伤。技能击杀同样可触发武士道。
- 冷却与增益使用单调时钟。死亡/重生清理状态，退房移除玩家状态；旧定时器通过状态对象及截止时间校验，避免关闭新角色或刷新后的效果。

## 造型与兼容

男女预设使用已有的翡翠武士服装纹理、4 种头发、上身 11～14 号饰品和下身 15～17 / 25～27 号饰品。`immobileUp` 使用部件类型 17，`immobileDown` 使用 18，按客户端 `SaveSuit` 格式生成。实际资源包中的默认造型资源引用全部存在。

旧角色获得新卡且保留旧卡；自动换装条件及缺少的专用武器资产见 [创建说明](samurai-creation.md)。初始生命配置与新角色默认值均为 1900。现有角色存档中的生命上限不强行改写。

## 已验证与尚待验证

无额外测试框架依赖的控制台回归工程：

```powershell
dotnet run --project tests/AvatarStar.Game.Tests/AvatarStar.Game.Tests.csproj -- "C:/Code/c#/AvatarStar"
```

106 项离线检查通过，包括范围/角度边界、冷却边界、一次性格挡、6 秒增益刷新、实际房间伤害、友军与旁观者排除、死亡与退出、JSON 存档、迁移幂等性、136/152 重放，以及解密后的 160/162/155/184 广播。模板通过 `luac -p`，服务端编译为 0 错误；最终构建报告现有 MySqlConnector 2.4.0 的一条 NU1902 依赖审计警告。本次没有变更数据库依赖版本。

尚未完成实机验收：客户端原生层是否接受新技能编号、动画骨骼和 VFX 的实际显示，需要进入游戏核对，不能用离线发包测试替代。此改动不修改客户端 exe 或 PDE，也不改动汉化、地图补丁和数据库启动配置。

当前服务端没有地图碰撞/视线查询接口；风步与反击使用现有位置同步，范围攻击采用几何判定，尚不处理墙体遮挡或台阶。风步路径宽度暂取 2 米，高度差容差 2 米；击退暂取水平 3、向上 0.5，均为服务端实现参数，并非从原脚本恢复的数值。

实机检查顺序：重启游戏服、重新登录武士、给四个主动技能及武士道加点、进入双人对战验证动画与命中，再检查格挡消耗和击杀光效。在关闭地图碰撞缺口前，不应把风步的几何位移视作完整的碰撞移动实现。
